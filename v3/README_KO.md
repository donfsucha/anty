# D-LOGIS CONTROL V3 실운영형

D-LOGIS CONTROL V3는 드론 배송 임무·기체·배터리·안전경보·배송증빙·운영기록을 Mission ID 기준으로 연결한 실행형 웹앱입니다.

## 1. 로컬 실행

### v3 폴더만 VS Code에서 연 경우

```bash
python3 -m http.server 5500
```

Chrome 주소창에서 다음 주소를 엽니다.

```text
http://localhost:5500
```

### anty-main 전체 폴더를 VS Code에서 연 경우

```bash
python3 -m http.server 5500
```

Chrome 주소창에서 다음 주소를 엽니다.

```text
http://localhost:5500/v3/
```

터미널에 주소를 입력하지 말고 Chrome 주소창에 입력합니다. 서버 종료는 터미널에서 실제 키보드의 Control 키와 C 키를 동시에 누릅니다.

## 2. 주요 구현 기능

- 조치 우선순위 중심 통합관제 대시보드
- 관제자·현장 조종자·배송 수령인 역할별 화면
- 4단계 신규 배송임무 등록
- 운항 승인, 자원 자동배정, 7개 비행 전 점검
- 이륙·일시대기·운항재개·긴급복귀·착륙·완료
- 드론 전송시각·서버 수신시각·명령 요청·ACK·적용확인시각 분리 기록
- 비행로그·명령이력·경보이력·배터리기록·점검표·배송증빙·감사로그 축적
- 9개 시트 XLSX 운영보고서 자동 생성
- JSON 전체 데이터 백업
- 카카오맵 무료 쿼터 우선, OpenStreetMap 자동 대체
- 브라우저 로컬 저장 및 PWA 오프라인 캐시

## 3. 숫자 표시 규칙

고도, 속도, 거리, 중량, 배터리, 온도, 통신품질, 풍속, 셀 편차, 데이터 지연 등 운영 수치는 소수점 한 자리로 저장하고 표시합니다.

예시:

```text
81.2 m
34.1 km/h
68.0 %
37.2 ℃
18.0 mV
```

`0.00003265983523` 같은 불필요한 긴 소수는 운영 화면과 일반 수치 보고서에서 표시하지 않습니다.

### 좌표는 정확도 보존을 위해 별도 규칙 적용

위도·경도를 소수점 한 자리로 줄이면 실제 위치 오차가 매우 커지므로 좌표만 예외로 처리합니다.

- 화면: 도·분·초(DMS), 초 단위 소수점 한 자리
- Excel·JSON 원본: WGS84 위도·경도 소수점 6자리

예시:

```text
화면: 37°30'13.2"N / 126°45'57.9"E
Excel: 37.503667 / 126.766083
```

## 4. 카카오맵 무료 사용 설정

1. 카카오 개발자센터에서 앱을 생성합니다.
2. Kakao Map API를 활성화합니다.
3. 플랫폼 설정에서 JavaScript SDK 도메인을 등록합니다.
4. 로컬 테스트 시 다음 도메인을 등록합니다.

```text
http://localhost:5500
```

5. Netlify 배포 후 발급된 도메인도 추가합니다.

```text
https://발급받은이름.netlify.app
```

6. D-LOGIS 앱에서 다음 순서로 입력합니다.

```text
관제센터 시작
→ 시스템설정
→ 카카오 JavaScript Key 입력
→ 카카오맵 무료 쿼터 모드 선택
→ 설정 저장·지도 다시 연결
```

카카오맵 키가 없거나 SDK 로딩이 실패하면 OpenStreetMap으로 자동 전환됩니다. 비용 방지를 위해 Google Maps 유료 결제계정 연동과 Kakao Biz Wallet 연결은 이 버전에 포함하지 않았습니다.

## 5. Excel 운영보고서

관제 화면 상단의 `운영보고서 XLSX` 버튼을 누르면 현재 브라우저의 실제 저장 데이터로 다음 시트를 생성합니다.

1. 운영요약
2. 임무목록
3. 비행로그
4. 명령이력
5. 경보이력
6. 배터리기록
7. 배송증빙
8. 점검표
9. 감사로그

각 행에는 가능한 경우 다음 항목이 함께 저장됩니다.

```text
기록ID
Mission ID
주문번호
기체ID
배터리ID
사용자
드론 전송시각
수신시각
명령 요청시각
ACK 수신시각
실제 적용확인시각
위도·경도
고도
속도
배터리 SOC·SOH·온도·셀 편차
통신품질
GNSS 위성 수
경보 현재값·기준값
조치 결과
```

Excel 생성을 위해 SheetJS 공식 CDN 스크립트를 사용하므로 최초 생성 시 인터넷 연결이 필요합니다.

## 6. Netlify 배포

Netlify Drop 화면에 `v3` 폴더 전체를 끌어다 놓습니다. 업로드할 폴더의 최상위에서 `index.html`이 바로 보여야 합니다.

올바른 구조:

```text
v3
├── index.html
├── styles.css
├── data.js
├── map.js
├── reports.js
├── app.js
├── service-worker.js
├── manifest.webmanifest
└── app-icon.svg
```

기존 Netlify 주소를 유지하려면 새 사이트가 아니라 기존 사이트의 Deploys 화면에 v3 폴더를 다시 업로드합니다.

## 7. 실제 운영 전 추가해야 하는 서버 기능

현재 V3는 브라우저 로컬 저장 기반의 정밀 시연·업무검증 버전입니다. 여러 사람이 동시에 사용하거나 실제 비행기록을 법적·계약적으로 보존하려면 다음 서버 기능이 필요합니다.

- 사용자 로그인과 역할별 권한
- PostgreSQL 등 중앙 데이터베이스
- 서버 수신시각과 NTP 시간동기화
- MAVLink 또는 제조사 SDK 게이트웨이
- 명령 ACK와 실제 비행모드 재확인
- 배송사진·전자서명 파일 저장소
- 데이터 백업·보존기간·암호화
- 위변조 방지 감사로그

실제 드론 명령은 기체·비행컨트롤러·통신장치·비상절차·운항승인 검증 후 활성화해야 합니다.
